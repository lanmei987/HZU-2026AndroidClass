# 第八周学习笔记 — Jetpack 核心（ViewModel & LiveData）

## 核心知识点

### 1. 为什么需要 ViewModel
- Activity/Fragment 在配置更改（如屏幕旋转）时会被销毁重建
- ViewModel 的生命周期比 Activity 长，数据不会因旋转而丢失
- 通过 `ViewModelProvider` 获取实例：`new ViewModelProvider(this).get(NewsViewModel.class)`

### 2. LiveData 响应式观察
- LiveData 是一个可观察的数据持有者，具有生命周期感知能力
- 只在 Activity/Fragment 处于活跃状态时通知观察者，避免内存泄漏
- 使用 `observe(LifecycleOwner, Observer)` 订阅数据变化

### 3. MutableLiveData vs LiveData
- `MutableLiveData` 可以调用 `setValue()`/`postValue()` 修改数据
- 对外暴露为 `LiveData`（只读），保证数据单向流动
- `postValue()` 用于子线程，`setValue()` 用于主线程

### 4. UI 状态与数据的单向流动
- View → ViewModel（用户操作触发加载）→ LiveData 更新 → View 自动刷新
- Activity 只负责观察和展示，不持有业务逻辑

### 5. 依赖配置
```groovy
implementation("androidx.lifecycle:lifecycle-viewmodel:2.8.7")
implementation("androidx.lifecycle:lifecycle-livedata:2.8.7")
```

## 踩坑记录

### 坑1：旋转屏幕后数据重复加载
- 原因：在 `onCreate` 中无条件调用 `loadNews()`
- 解决：判断 `viewModel.getNewsLiveData().getValue() == null` 时才首次加载

### 坑2：子线程更新 LiveData 崩溃
- 原因：Retrofit 回调在子线程，使用了 `setValue()`
- 解决：改用 `postValue()`，它会自动切换到主线程更新

## 关键代码片段

```java
// ViewModel 中持有 LiveData
public class NewsViewModel extends ViewModel {
    private final MutableLiveData<List<News.Article>> newsLiveData = new MutableLiveData<>();

    public LiveData<List<News.Article>> getNewsLiveData() {
        return newsLiveData;
    }

    public void loadNews() {
        // 网络请求...
        newsLiveData.postValue(data);
    }
}

// Activity 中观察
viewModel.getNewsLiveData().observe(this, articles -> {
    adapter.updateData(articles);
});
```
